# 数据准备与向量知识库构建

> 这是 LLM 应用的"数据工程"环节——把用户的原始文档变成可供 LLM 检索和使用的知识。数据质量直接决定 RAG 效果的上限。

---

## 一、整体流程

```
原始文档 → 文档加载 → 文本清洗 → 文本分割 → Embedding向量化 → 存入向量数据库
   ↑                                                              ↓
用户上传                                                    语义检索匹配
                                                              ↓
                                                     LLM 生成回答
```

## 二、文档加载

不同格式的文档需要不同的加载器。LangChain 提供了 80+ 种文档加载器：

| 文档格式 | 加载方式 | 注意点 |
| --- | --- | --- |
| PDF | `PyPDFLoader` / `PDFPlumberLoader` | PDF 中的表格和图片很难正确提取，优先用 `PDFPlumberLoader` |
| Markdown | `UnstructuredMarkdownLoader` | 保留标题层级，有助于后续分块保持语义完整性 |
| TXT | 直接 `open()` 读取 | 最简单的格式，但缺乏结构信息 |
| HTML/网页 | `WebBaseLoader` / `BSHTMLLoader` | 需要去除导航栏、广告等噪音 |
| Word | `Docx2txtLoader` | 注意处理表格格式 |
| CSV/Excel | `CSVLoader` / Pandas | 保留表格结构信息，不要让分块器把一行数据切开 |

## 三、文本分割（Chunking）

这是 RAG 最重要的调参环节。分割策略直接影响检索质量：

| 策略 | 做法 | 适用场景 |
| --- | --- | --- |
| 固定字符数 | 每 N 个字符切一个块 | 最简单但效果最差，会在句子中间断开 |
| 固定字符 + 重叠 | 每 N 字符，重叠 M 字符 | 减少"关键信息刚好在边界"的问题 |
| 按句子切分 | 用句号/问号/感叹号做分隔 | 中文效果好，但长段落会变成超大块 |
| 递归分割（推荐） | 先按段落切，太长的再按句子切，还不够就按字符切 | **LangChain 默认方案，生产首选** |
| 语义分割 | 用 Embedding 模型的注意力分数找"语义边界" | 效果最好但实现复杂 |

### Chunk Size 的选择

- **太小（<100 tokens）**：信息碎片化，检索到的内容不足以回答任何问题
- **太大（>1000 tokens）**：检索精度下降，噪音增多，且消耗更多 Token
- **推荐起始值**：256-512 tokens（OpenAI Embedding 模型的最优区间），然后根据实际效果调整

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每个块的最大字符数
    chunk_overlap=50,      # 块之间的重叠字符数（保持上下文连续性）
    separators=["\n\n", "\n", "。", "！", "？", " ", ""]  # 分割优先级
)
chunks = splitter.split_text(document)
```

## 四、向量化与入库

```python
from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings

# 1. 选 Embedding 模型
embedding = OpenAIEmbeddings(model="text-embedding-3-small")

# 2. 创建向量库
vectordb = Chroma.from_documents(
    documents=chunks,          # 分割好的文本块
    embedding=embedding,       # Embedding 模型
    persist_directory="./chroma_db"  # 持久化路径
)

# 3. 后续使用时加载（不需要重新 Embedding）
vectordb = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embedding
)
```

## 五、数据质量检查清单

上线前确认：
- [ ] 文档中的乱码、特殊字符已清理
- [ ] 表格、图片中的关键信息没有被丢失
- [ ] 同一份文档没有重复入库
- [ ] Chunk Size 是否合适——随机抽几个查询，看检索到的 Chunk 是否包含完整答案
- [ ] 如果用户删除了文档，向量库中对应的 Chunk 是否同步删除
