# 第一步：模型选型

> 选模型是 LLM 应用开发的第一步，也是最影响成本、效果和上线速度的决策。本文给出一套系统化的模型选型框架。

---

## 一、选型维度

不要只看"谁更强"，要同时看六个维度：

| 维度 | 问题 | 权重 |
| --- | --- | --- |
| **能力** | 这个任务它做得好吗？ | ⭐⭐⭐⭐⭐ |
| **延迟** | 回复要多快？用户能等多久？ | ⭐⭐⭐⭐ |
| **成本** | 每 1000 次调用多少钱？ | ⭐⭐⭐⭐ |
| **上下文窗口** | 需要一次处理多长的内容？ | ⭐⭐⭐ |
| **稳定性/可用性** | API 会不会频繁限流？有没有多区域部署？ | ⭐⭐⭐ |
| **合规** | 数据能不能出境？是否需要私有化部署？ | ⭐⭐⭐（国内场景） |

## 二、按场景推荐

| 场景 | 推荐模型 | 原因 |
| --- | --- | --- |
| 普通对话/问答 | GPT-4o-mini / DeepSeek-V3 | 成本低，效果好，覆盖绝大多数任务 |
| 复杂推理/编程 | Claude Sonnet / GPT-4o | 逻辑推理和代码生成能力更强 |
| 长文档处理 | Claude 3/3.5 (200K 上下文) / Gemini 1.5 Pro (1M+) | 上下文窗口大 |
| 中文场景 | DeepSeek / 通义千问 / GLM-4 | 中文理解和生成能力最优 |
| 私有化部署 | Qwen2.5 / LLaMA 3 / DeepSeek | 开源，可本地部署 |
| 图像理解 | GPT-4o / Claude 3.5 Sonnet / Gemini | 多模态能力 |
| 极致低成本 | GPT-4o-mini / DeepSeek | 每百万 Token 不到 $1 |

## 三、选型决策流程

```
1. 先定需求
   - 任务类型？（对话 / 推理 / 代码 / 翻译 / 摘要）
   - 延迟要求？（实时 <2s / 可以等 10s / 批量处理几小时都行）
   - 数据合规？（能上云 / 必须本地）
   
2. 用便宜模型快速验证
   → GPT-4o-mini 跑通整个流程，确认产品方向可行
   
3. 发现问题后按需升级
   → 准确率不够 → 换更强的模型
   → 太慢 → 换更快的模型或加缓存
   → 太贵 → 换便宜模型 + 更好的 Prompt
   
4. 不要只绑一个模型
   → 用 LiteLLM 或自建网关做多模型路由和 Fallback
   → "A 模型不行时自动切 B 模型"是生产环境的基本保障
```

## 四、API 还是私有化？

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| **API 调用** | 零运维、最新模型、按量付费 | 数据出境（国内）、供应商锁定、成本不可控 |
| **私有化部署** | 数据安全、成本可控（大规模）、可定制 | 运维复杂、模型推理需要 GPU、更新滞后 |

**建议**：开发阶段用 API 快速验证，产品验证后有需求再考虑私有化。

## 五、常见错误

- **选最贵最强的一步到位** — 需求都没验证清楚就上 GPT-4o，月账单惊人
- **只看评测不实测** — 网上说 A > B，但在你的具体任务上可能 B > A。用自己的数据做 A/B 测试
- **忽略延迟** — GPT-4o 可能比 GPT-4o-mini 强 5%，但慢了 3 倍——对用户体验的影响可能远超那 5%
