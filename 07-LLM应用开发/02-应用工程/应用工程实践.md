# 应用工程实践

> 将 LLM 原型变成可维护、可监控、可扩展的生产应用，需要在 Prompt 之外建设一套工程基础设施。

---

## 一、从 Demo 到生产的鸿沟

一个 Jupyter Notebook 里能跑的 LLM Demo，放到生产环境中会遇到这些新问题：

| Demo 阶段 | 生产阶段 | 解决方案 |
| --- | --- | --- |
| 在 Notebook 里调 API | 处理并发请求、异步调用 | 异步框架（FastAPI + asyncio） |
| 手动测几条 Prompt | 持续回归测试、A/B 对比 | Prompt 版本管理 + 自动化评测 |
| 看终端日志 | 集中式日志、链路追踪 | 可观测性平台（Langfuse / LangSmith） |
| 忽略成本 | Token 月度账单数万 | 缓存（语义缓存/精确缓存）+ 成本监控 |
| 无错误处理 | 用户不能看到 500 错误 | 重试、Fallback、优雅降级 |

## 二、API 调用工程化

### 错误处理

```python
import asyncio
from openai import AsyncOpenAI, RateLimitError, APITimeoutError

async def call_llm_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = await client.chat.completions.create(
                model="gpt-4o-mini",
                messages=messages,
                timeout=30,
            )
            return response
        except RateLimitError:
            wait = 2 ** attempt  # 指数退避
            await asyncio.sleep(wait)
        except APITimeoutError:
            if attempt == max_retries - 1:
                raise  # 最后一次抛出
            await asyncio.sleep(1)
```

### 并发控制

```python
import asyncio

# 同时处理多个请求，但控制并发数
semaphore = asyncio.Semaphore(10)  # 最多 10 个并发

async def process_with_limit(query):
    async with semaphore:
        return await call_llm(query)
```

## 三、Prompt 版本管理

Prompt 不是"写好就不变了"——它需要像代码一样管理：

1. **用 Git 管 Prompt**：把 Prompt 模板放在 `.yaml` 或 `.py` 文件中，和代码一起做版本控制
2. **区分 Prompt 版本**：每次改 Prompt 记录版本号，方便回滚
3. **A/B 测试**：新 Prompt 先在 10% 流量上跑，效果好再全量
4. **评测回归**：每次改 Prompt 后跑一轮评测集，确保不退化

## 四、缓存策略

| 缓存类型 | 原理 | 节省比例 | 实现 |
| --- | --- | --- | --- |
| 精确缓存 | 相同输入 → 直接返回缓存结果 | 10-30% | Redis `key = hash(input)` |
| 语义缓存 | 语义相似的输入 → 返回缓存结果 | 30-60% | 向量检索 + 相似度阈值 |

```python
# 最简单的精确缓存
import hashlib, json, redis

r = redis.Redis()

def cached_llm_call(messages):
    key = hashlib.md5(json.dumps(messages).encode()).hexdigest()
    cached = r.get(key)
    if cached:
        return json.loads(cached)
    result = call_llm(messages)
    r.set(key, json.dumps(result), ex=3600)  # 缓存 1 小时
    return result
```

## 五、成本控制

- **设定 Token 预算告警**：监控每天的 Token 消耗，超过阈值告警
- **限制单用户调用**：防止滥用——设置每个用户的 RPM（每分钟请求数）和日限额
- **用便宜模型做"判断"**：对简单任务（分类、抽取），GPT-4o-mini 通常够用，不需要 GPT-4o
- **优化 Prompt 长度**：不要无脑把超大上下文拼进去，用检索/摘要压缩
