# 典型场景代码对比
## 错误处理
**Python**（异常机制）：

```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"Error: {e}")
```

**Go**（显式错误）：

```go
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

result, err := divide(10, 0)
if err != nil {
    fmt.Printf("Error: %v", err)
}
```

## 并发编程
**Python**（协程）：

```python
import asyncio

async def fetch(url):
    print(f"Fetching {url}")
    await asyncio.sleep(1)
    return "data"

async def main():
    results = await asyncio.gather(fetch("url1"), fetch("url2"))
    print(results)

asyncio.run(main())
```

**Go**（goroutine）：

```go
func fetch(url string, ch chan<- string) {
    fmt.Printf("Fetching %s\n", url)
    time.Sleep(1 * time.Second)
    ch <- "data"
}

func main() {
    ch := make(chan string)
    go fetch("url1", ch)
    go fetch("url2", ch)
    fmt.Println(<-ch, <-ch)
}
```

# 设计哲学差异
1. **动态 vs 静态**：
    - Python 通过 `def`/`class` 实现**灵活的动态类型**
    - Go 通过 `func`/`type` 强制静态类型检查
2. **异常处理**：
    - Python 的 `try`/`raise` 实现集中错误处理
    - Go 通过 `error` 返回值强制逐级处理
3. **并发模型**：
    - Python 的 `async`/`await` 在语言层面支持协程
    - Go 的 `go`/`chan` 提供更底层的并发原语

Go 中不要试图用 `**panic**` 替代异常机制，在 Python 中不要过度依赖类型提示进行静态检查。
