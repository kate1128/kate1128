以下是 Python 异常处理与 Go 错误处理的详细对比说明，包含 Python 异常处理的核心机制、常见用法以及与 Go 的差异：

#  基本异常处理结构对比
## Python 异常处理 (`try`/`except`/`finally`)
```python
try:
    # 可能抛出异常的代码
    file = open("data.txt", "r")
    content = file.read()
    num = int(content)
except FileNotFoundError as e:
    # 处理特定异常
    print(f"文件不存在: {e}")
except ValueError:
    # 处理其他异常
    print("内容不是有效数字")
else:
    # 无异常时执行
    print(f"读取成功，数值为: {num}")
finally:
    # 无论是否异常都执行
    file.close() if 'file' in locals() else None
```

## Go 错误处理 (显式检查)
```go
func readFile() (int, error) {
    // 显式检查错误
    data, err := os.ReadFile("data.txt")
    if err != nil {
        if errors.Is(err, os.ErrNotExist) {
            fmt.Printf("文件不存在: %v", err)
            return 0, err
        }
        return 0, fmt.Errorf("读取失败: %w", err)
    }

    num, err := strconv.Atoi(string(data))
    if err != nil {
        fmt.Println("内容不是有效数字")
        return 0, err
    }

    fmt.Printf("读取成功，数值为: %d", num)
    return num, nil
}

// 调用
num, err := readFile()
if err != nil {
    // 处理错误
}
```

**核心差异**：

+ Python 使用结构化异常处理，Go 通过返回值显式传递错误
+ **Python 的 **`**except**`** 块类似 Go 的 **`**if err != nil**`** 检查**
+ **Python 的 **`**finally**`** 对应 Go 的 **`**defer**`

# 异常传播机制对比
## Python 异常自动传播
所以异常会自动往上抛，意思是最外层处理一次异常就 ok 了？

```python
def func_a():
    raise ValueError("深层错误")

def func_b():
    func_a()  # 异常自动向上传播

try:
    func_b()
except ValueError as e:
    print(f"捕获到错误: {e}")  # 输出: 捕获到错误: 深层错误
```

## Go 手动传递错误
```go
func FuncA() error {
    return fmt.Errorf("深层错误")
}

func FuncB() error {
    if err := FuncA(); err != nil {
        return fmt.Errorf("funcB失败: %w", err)
    }
    return nil
}

func main() {
    if err := FuncB(); err != nil {
        fmt.Printf("捕获到错误: %v", err)  // 输出: 捕获到错误: funcB失败: 深层错误
    }
}
```

**关键差异**：

+ Python 异常自动冒泡直到被捕获
+ Go 必须逐层返回错误，可通过 `%w` 包装错误信息

# 自定义异常/错误对比
## Python 自定义异常类
raise 怎么用的？

```python
class NetworkError(Exception):
    """自定义网络异常"""
    def __init__(self, code):
        self.code = code
        super().__init__(f"网络错误，状态码: {code}")

try:
    raise NetworkError(500)
except NetworkError as e:
    print(e.code)  # 输出 500
```

## Go 自定义错误类型
```go
type NetworkError struct {
    Code int
}

func (e *NetworkError) Error() string {
    return fmt.Sprintf("网络错误，状态码: %d", e.Code)
}

func main() {
    err := &NetworkError{Code: 500}
    if ne, ok := err.(*NetworkError); ok {
        fmt.Println(ne.Code)  // 输出 500
    }
}
```

# 资源清理方式对比
## Python 的 `finally`
```python
try:
    file = open("data.txt")
    process(file)
except IOError as e:
    print(f"文件错误: {e}")
finally:
    file.close()  # 确保资源释放
```

## Go 的 `defer`
```go
func processFile() error {
    file, err := os.Open("data.txt")
    if err != nil {
        return err
    }
    defer file.Close()  // 确保函数返回前关闭

    // 处理文件...
    return nil
}
```

# 错误处理最佳实践对比
## Python 推荐模式 (EAFP)
**Easier to Ask for Forgiveness than Permission**

```python
try:
    value = my_dict["key"]
except KeyError:
    value = default_value
```

## Go 推荐模式 (显式检查)
**Look Before You Leap**

```go
if value, ok := myMap["key"]; ok {
    // 使用 value
} else {
    value = defaultValue
}
```

# 核心差异总结表
| **维度** | **Python 异常处理** | **Go 错误处理** |
| :--- | :--- | :--- |
| **错误传递** | 自动冒泡传播 | 显式逐层返回 |
| **错误类型** | 丰富的内置异常类 | 简单错误接口 + 自定义类型 |
| **资源清理** | `finally`
 代码块 | `defer`
 延迟执行 |
| **错误信息** | 异常对象包含调用栈 | 需手动包装错误 (`%w`) |
| **性能影响** | 异常捕获成本较高 | 错误返回值无额外开销 |
| **代码风格** | 减少错误检查代码量 | 错误检查代码显式可见 |
| **适用场景** | 适合预期可能失败的操作 | 适合需要精细控制错误流的场景 |

# 典型场景代码对比
## 数据库操作错误处理
**Python**：

```python
try:
    conn = connect_db()
    conn.execute_query("SELECT...")
except ConnectionError as e:
    print(f"连接失败: {e}")
except QueryError as e:
    print(f"查询错误: {e}")
else:
    print("操作成功")
finally:
    conn.close()
```

**Go**：

```go
func DBQuery() error {
    conn, err := ConnectDB()
    if err != nil {
        return fmt.Errorf("连接失败: %w", err)
    }
    defer conn.Close()

    if err := conn.ExecuteQuery("SELECT..."); err != nil {
        return fmt.Errorf("查询错误: %w", err)
    }

    fmt.Println("操作成功")
    return nil
}
```

# 开发建议
## Python 异常处理原则
什么叫过度捕获？

+ **避免过度捕获**：不要用宽泛的 `except:`，明确指定异常类型
+ **使用上下文管理器**：替代 `try-finally` 进行资源管理

```python
with open("data.txt") as f:  # 自动处理关闭
    content = f.read()
```

## Go 错误处理技巧
+ **错误包装**：使用 `fmt.Errorf("... %w", err)` 保留原始错误
+ **错误类型断言**：精确处理特定错误

```go
if ne, ok := err.(*NetworkError); ok {
    // 处理网络错误
}
```
