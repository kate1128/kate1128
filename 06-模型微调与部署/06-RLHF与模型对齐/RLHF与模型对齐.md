# RLHF 与模型对齐（Alignment）

> 本笔记定位：全文围绕"如何让大模型成为一个既聪明又听话、既有用又无害的助手"展开。读完要能回答：对齐是什么、为什么必需、RLHF 三阶段各自在干什么、PPO 在强化学习宏观上的机制、DPO 如何免去 RL，以及怎么评估。与 SFT/LoRA 类微调的关系放在文末衔接。

## 一、概念引入：什么是"对齐"（Alignment）

"对齐"这个词翻译自英文 Alignment。它的意思是：**让模型的行为目标和人类的价值偏好保持一致**。预训练的大模型只是一个"语言概率器"——它的目标是最大化"下一个 token"的预测概率，它学会了语法、事实知识和世界常识，但它并不知道人类希望它"说话有礼貌、回答问题要准确、不编造、不说危险的话"。

对齐就是在这第一阶段的"能力"之后，补上第二阶段"价值观"。业界经典的三原则是 OpenAI 提出的 **HHH**：

- **Helpful（有用）**：认真理解用户问题，给出充分、具体、可靠的回答，而不是敷衍或偏题。
- **Honest（诚实）**：不知道就承认不知道，不编造，不把猜测说成事实。
- **Harmless（无害）**：拒绝帮助完成危险或违规的请求，不输出歧视、暴力、违法内容。

对齐的手段可以很朴素（好的 prompt 工程、系统提示词），也可以很工程化（SFT 指令微调、RLHF、DPO 等训练方法）。本文重点讲的是**训练层面**的 RLHF 及它的轻量替代者 DPO。

## 二、为什么需要对齐：能力之外的两大痛点

预训练后的基座模型直接面向用户会暴露两类问题：

1. **幻觉（Hallucination）**：模型基于概率分布续写，对不确定的知识会"一本正经地编"——它不是在撒谎，而是它不知道自己不知道。据统计对齐后的模型在事实验证类评测上错误率显著下降。
2. **有害内容与滥用**：基座模型可能会老老实实地回复"怎么制作炸弹""怎么写攻击性邮件"。它不是坏，而是它压根没有"该不该说"的概念。

另外一个常被忽视的痛点：**预训练的目标（续写）和用户的实际目标（答题、总结、写代码）不一致**。模型把"问题 + 答案"整体看成一段文本去续写，导致它倾向于"继续编故事"而不是"精确回答"。对齐 (尤其是 RLHF) 恰恰把优化目标从"下一个 token 的似然"换成了"人类偏好的奖励"。

一句话：**预训练决定"模型能不能回答"，对齐决定"模型该不该这么回答、答得好不好"**。前者是能力（capability），后者是品行（behavior）。

## 三、对齐 vs 传统微调（SFT）：区别与关系

| 对比维度 | 传统监督微调 SFT | RLHF 对齐 |
| --- | --- | --- |
| 学习信号 | 标注好的"问-答"样例（监督标签） | 人类/模型的偏好反馈（相对比较） |
| 优化目标 | 最大化标签序列的似然（交叉熵） | 最大化奖励信号（人类偏好打分） |
| 数据形态 | 需要一个标准答案 | 只需要两个(或多个)答案的相对好坏 |
| 覆盖场景 | 学会某个任务的格式与风格 | 学会"什么样的回答更受认可"的品味 |
| 局限性 | 学的是"样例的平均水平"，难以超越数据集；对齐不足 | 需要额外训练奖励模型/偏好数据，成本高、不稳定 |

关系：**SFT 是 RLHF 的"第一步"和"底座"**。RLHF 三阶段里的第一步就是 SFT。没有 SFT，模型连"回答问题"的格式都不会；没有 RLHF，模型可能只会机械复述 SFT 里见过的答案而不会举一反三、不会拒绝越界请求。两者是"先教会干活，再教会做人"的递进关系。

## 四、核心原理：RLHF 三阶段全流程

### 阶段一：SFT 监督微调（给模型装"聊天形态"）

收集大量人类/模型生成的"指令-预期回复"对，用标准交叉熵做监督微调。这步之后模型已经具备"像 ChatGPT 一样说话"的形态，但还没有偏好优化的能力。注意：如今很多机构会直接用高质量人工/模型数据做 SFT，SFT 的数据质量直接决定天花板。

### 阶段二：训练奖励模型 RM（Reward Model）

这是 RLHF 的关键创意，目的是把"人类的主观偏好"量化成一个可以反复查询的打分函数。

**怎么构造偏好数据**：收集一批提示（prompt）x，对每个 prompt 让模型生成多个候选回答 y1、y2、...，然后请标注员（人或更强的模型）比较这些回答，标出"哪个更好"。数据以 pair 形式存在：(x, y_w, y_l)，y_w 是更被喜欢的（winner），y_l 是较差的（loser）。这种**相对比较**形式的标注比"给 1~5 打分"更稳定——人容易比较两件事，不容易给抽象分数。

**reward model 怎么训练（Bradley-Terry 模型）**：奖励模型 rθ(x, y) 是一个"给 (prompt, 回答) 输出一个标量分数"的网络。我们假设：标注员更喜欢 y_w 而不是 y_l 的概率，服从 Bradley-Terry (BT) 模型——即 logistic 形式的偏好函数：

```
P( y_w 优于 y_l ) = σ( rθ(x, y_w) - rθ(x, y_l) )
                 = 1 / ( 1 + e^( -( rθ(x,y_w) - rθ(x,y_l) ) ) )
```

直观解读：**奖励模型给 y_w 的分数减掉给 y_l 的分数，再进 sigmoid，就得到一个介于 0 到 1 的"偏好概率"**。分数差越大，概率越接近 1。训练时就把这个概率的负对数（二元交叉熵/NLL）当作损失，让奖励模型学会"每次比较都站对队"。BT 模型的本质假设是——人类偏好可以用一个"潜在分数"（reward）的差值来建模，这大大简化了排序问题：排序数据只需要看两两差值，而奖励模型的输出天然就是那个分数。这比直接训练一个"给回答打绝对分"的回归模型稳定得多——因为标注时原始数据本来就是"两两比较"，RM 只是把这个比较信号反推成打分函数。

批量训练时，同一 prompt 有多个回答，通常取"每个 pair 都是 winner/loser 的两两损失"或者"把同 prompt 的所有回答排列组合成 pair"。训练好后，同一 (x, y) 对应分值 rθ(x, y) 越高，代表"更像人类偏好的回答"。

### 阶段三：RL 强化学习 —— 用 PPO 微调策略模型

现在把 RM 当"裁判"，用强化学习去更新生成模型（策略模型）π，让它生成"裁判打高分"的回答。

**PPO（Proximal Policy Optimization，近端策略优化）的核心组件**：

- **策略网络（Actor / policy）**：就是我们要微调的生成模型 πθ。它根据 prompt 采样出回答。它的可训练参数是我们真正想更新的。
- **价值网络（Critic / value）**：一个辅助网络 V(s)，估计"当前状态（已生成的 token）往后能拿到的总奖励期望"。它用于计算优势函数（advantage）——即"这一步的实际回报比预期好还是差"，引导策略向"超预期"的动作加大概率。
- **reward（奖励信号）**：回答整体生成完之后，交给 RM 打分 rθ(x, y)，这就是这个"生成动作序列"的总奖励。
- **参考模型（SFT 模型，冻结）**：不更新参数的 π_ref，用来做 KL 惩罚。

**关键机制一：为什么需要参考模型做 KL 惩罚？**

如果只按 RM 分数优化，策略模型会很快学习"钻空子"：找到几个高分回答的句式疯狂复读，或者干脆扭曲语言让 RM 给出畸形高分，导致生成质量崩坏（奖励黑客 reward hacking）。所以当代价函数中加上**对参考模型的 KL 散度惩罚**，限制策略模型不能偏离 SFT 模型太远：

```
总目标 ≈ E[ RM 奖励 ] - β * KL( πθ(·|x) ‖ π_ref(·|x) )
```

β 是控制"顺从奖励 vs 保持语言自然"的平衡系数。KL 散度惩罚项的作用是：如果策略为了吃奖励而输出不自然的句子，即使 RM 分数高，也会因为偏离参考模型被扣分。这既保证生成文本仍然句句通顺、语义在分布内，也防住了奖励黑客。

**关键机制二：clip 裁剪（PPO 的核心稳定器）**

PPO 是 on-policy 的强化学习，它每采样一批数据就要更新若干步。它的目标函数里用了一个"重要性采样比"：

```
ratio = πθ(new) / πθ_old   # 新策略在旧策略下这个动作的相对概率
```

如果 ratio 过大（新策略一步就把某个动作的概率改得太狠），更新就会震荡甚至崩溃。PPO 的做法是对 ratio 做 clip：

```
L_clip = E[ min( ratio * A,  clip( ratio, 1-ε, 1+ε ) * A ) ]
```

意思非常直白：**当优势 A 为正（动作该鼓励）时，上限封在 1+ε，不让它一口吃成胖子；当 A 为负（动作该抑制）时，下限封在 1-ε，不让它一步就把它打没**。ε 通常取 0.1~0.2。这条规则保证了每次更新的步长被限制在一个"信任域"里，这也是"Proximal（近端/邻近）"这个单词的含义——只敢在旧策略附近小步挪动。clip 是 PPO 稳定性最大的功臣，也是与 TRPO 昂贵的二阶信任域方法相比更简单高效的替代方案。

**PPO 宏观流程（机制思路，不写死公式）**：

```
循环（采样 + 更新）：
1. 用策略 πθ 对一批 prompt 采样回答（生成过程即"交互环境"）
2. 对每个回答用 RM 打分，得到奖励 rθ(x, y)
3. 用参考模型计算 KL 惩罚 → 修正奖励：reward' = rθ - β*KL
4. 计算每个 token 位置的优势估计（用价值网络 V 做基准）
5. 用 clip 目标做若干轮梯度更新（同时小步更新价值网络）
6. 回到第 1 步，用更新后的策略再次采样
```

核心思想归纳为一句：**"又想要大步前进，又怕迈错步摔跟头"，于是把每次步长限制在近端小步内（clip），同时用参考模型的 KL 惩罚当护栏，让模型沿着『RM 认为人类更喜欢』的方向稳步爬坡**。

> 补充：除 PPO 外，还有 GRPO（DeepSeek-R1 用的去价值网络变体）、REINFORCE 等 on-policy 方法，原理同构：采样、奖励、加 KL、小步更新。

### 三阶段全流程一张图记忆

```
预训练基座模型
   ↓ 用 (指令, 人工回答) 做 SFT →  阶段一：会说话
   ↓ 用偏好 pair 训奖励模型 RM →  ±阶段二：有裁判
   ↓ 用 RM 当奖励 + PPO + KL 约束微调策略 → 阶段三：会讨人喜欢
   → 得到对齐后的模型（如真实 ChatGPT 的路线）
```

（阶段二 RM 可以与阶段三并行准备：RM 在阶段一完成后上线，阶段三用冻结的 RM 打分。）

## 五、轻量替代方案：DPO —— 不做 RL 也能对齐

**DPO（Direct Preference Optimization，直接偏好优化）**回答了一个关键问题："RLHF 那么贵又不稳（要训 RM、要采样、要调 PPO 这么多超参），能不能不玩 RL 也能直接对齐？"

DPO 的核心洞察是：**偏好优化目标存在一个解析解——最优策略可以写成参考策略乘上一个与奖励函数有关的比例形式**，于是可以把这个关系反着用：用参考模型 π_ref 和最优策略 πθ 的比值直接替换掉奖励函数，再把这个"隐式奖励"代入标准的偏好损失（Bradley-Terry），就得到一个**只依赖 πref 和 πθ 的纯监督式损失**：

```
L_DPO ≈ -E[ log σ( β*log(πθ(y_w)/π_ref(y_w)) - β*log(πθ(y_l)/π_ref(y_l)) ) ]
```

不纠结公式，只讲机制思路：**DPO 不需要额外的奖励模型**，它把"RLHF 里奖励最大化"的工作直接编码进了"策略模型对偏好数据的学习"里——本质是一个带 KL 约束（πref 起同样作用）的最优策略推导。你只需要和 RM 阶段一样的偏好数据 (x, y_w, y_l)，然后训练 πθ 让 y_w 的概率相对 y_l 变大即可。**训练稳定、超参少、显存省、不用采样数据**，被证明在很多场景能与 PPO+R LHF 打平甚至更好。

| 对比 | RLHF(PPO) | DPO |
| --- | --- | --- |
| 是否需要奖励模型 | 需要单独训一个 RM | 不需要，隐式奖励 |
| 是否需要 on-policy 采样 | 需要，成本高 | 不需要 |
| 训练稳定性 | 超参多，易崩 | 稳定得多 |
| 计算/显存开销 | 大 | 小（约等于一次 SFT+ 一点） |
| 效果上限 | 理论更高（直接优化奖励） | 论文证明打平/接近 |
| 适用场景 | 预算足、要极致对齐的大厂 | 个人/小团队微调的默认选择 |

## 六、对齐评估：怎么知道对齐了没有

对齐评估常见于两类：

1. **能力/有用性评测**：MMLU（综合知识）、GSM8K（数学）、HumanEval（代码）、MMMU 等多任务 benchmark，衡量"Helpful"。
2. **对齐/安全评测集**：如 Anthropic 的 HHH 数据集与 Constitutional AI 评测、OpenAI 的"从对抗样本中测试 jailbreak"、各种 red-teaming（红队对抗）数据，测"Honest + Harmless"。还有 HELM、SafetyBench、大模型安全基准（如 CValues）等。

工程上做法通常是：**自动指标（如 GPT-4 当裁判对对齐前后回答打分）+ 人类偏好标注抽样 + 对抗性 prompt（试图诱导模型越狱/编造）回归测试**。对齐训练常出现"对齐税"——安全训练可能略降通用能力，所以评估要两者一起看。

## 七、常见问题与业界观点

1. **RLHF 是暴力毁灭模型能力的吗？** 不完全是。KL 惩罚+低学习率下，能力衰减可控；但做得差确实会"洗脑"掉一部分多样性。
2. **奖励模型会放大人类偏见** 标注员偏好不对齐，RM 就学偏；这也是各家只公开"对齐后的模型"而不公开 RM 的原因之一。
3. **奖励黑客**：模型发现绕开语言约束能得分更高时，会产出乱码或自说自话；ε-clip 与 KL 惩罚正是为此而设，业界仍需持续对抗。
4. **越狱（jailbreak）**：对齐不是永久的，提示词攻击能诱导模型绕开安全护栏，这也说明对齐是一个需要持续维护的工程问题。
5. **业界观点**：OpenAI 马尔库斯等人认为 RLHF 是"最接近解决对齐问题的实用框架"；但也有批评（"RLHF 只是拟合标注员的偏好统计，而非真正的价值观"）。2024 年后 DPO / GRPO / RLAIF（AI 反馈强化学习）兴起，说明业界共识是"对齐方法在快速迭代，但'用偏好信号优化行为'这个大方向成立"。

总结一句话：**对齐 = 用 SFT 打底教格式 + 用偏好数据/奖励模型量化"人类喜好" + 用 PPO（或免 RL 的 DPO）在 KL 护栏内沿着奖励爬坡**。凡是要训练真正的助手型模型，这段绕不开。
