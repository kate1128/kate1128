# 非结构化数据（Unstructured Data）

> 无预定义格式或数据模型的信息，占企业数据总量的 80% 以上。文本、图像、音频、视频是最常见的类型。**这是 LLM 最主要的"原材料"**。

## 是什么

非结构化数据的特征：**形式多样、无固定模式、无法直接用表格行列来表达**。

与结构化数据的"填表"逻辑不同，非结构化数据是自然产生的——一封邮件、一段对话录音、一张 CT 影像、一篇新闻稿，它们在被存储时没有经过 Schema 约束。

正因如此，非结构化数据的价值挖掘长期依赖人工。而 LLM 的出现改变了这一点：GPT、Claude 等模型能直接从非结构化文本中提取信息、总结要点、回答问题。

## 为什么重要

- **LLM 的核心饲料**：GPT 的训练数据绝大部分是非结构化文本——网页、书籍、论文、代码仓库
- **RAG 的场景之源**：企业做 RAG，最终目标是让 LLM"读懂"内部非结构化文档（PDF、合同、会议纪要、代码库）
- **AI 的真正战场**：结构化数据只占企业数据约 20%，真正的金矿在非结构化的 80% 里

## 三类数据对比

| 维度 | 结构化 | 半结构化 | 非结构化 |
| :--- | :--- | :--- | :--- |
| 结构严格性 | 严格二维表模型 | 含标签标记，结构松散 | 无预定义结构 |
| 典型技术 | SQL、OLAP | JSON/XML 解析、jq | NLP、计算机视觉、ASR |
| 代表格式 | 数据库表 | JSON/XML/日志 | 文本/图像/音视频 |
| LLM 的角色 | Text-to-SQL 查询 | API 输出格式 | 训练数据和推理输入 |

## 关键要点

- **核心处理技术**：NLP（文本）、CV（图像/视频）、ASR（语音转文字）
- **Embedding 是桥梁**：将非结构化的文本/图像转化成向量，才能被机器高效检索和比较
- **存储系统**：文件系统、对象存储（S3/MinIO）、NoSQL（MongoDB）、向量数据库
