# 样本提示（Few-shot / One-shot / Zero-shot Prompting）

> 通过 Prompt 中提供的示例数量来引导 LLM 执行任务的方法。从零示例（Zero-shot）到一个示例（One-shot）再到几个示例（Few-shot），示例越多模型对任务的理解越精确——但也有边际收益递减。

## 是什么

三种模式的核心区别只有一个：**Prompt 里有没有示例，以及有多少个**：

| 模式 | 示例数量 | Prompt 形式 | 适用场景 |
| --- | --- | --- | --- |
| Zero-shot | 0 个 | "将以下文本翻译成英文：今天天气真好" | 简单/常见任务，模型本身已经擅长 |
| One-shot | 1 个 | 给一个翻译示例 + "将以下文本翻译成英文：..." | 中等难度，需要明确输出格式 |
| Few-shot | 2-5 个 | 给几个翻译示例 + 新输入 | 复杂任务、特定格式、模型不擅长的领域 |

## 为什么重要

- **Prompt 设计的基础方法论**：理解了这三种模式，就知道什么时候只需要一句话（Zero-shot），什么时候该花精力写几个好示例（Few-shot）
- **成本权衡**：示例越多 → Prompt 越长 → Token 消耗越大。一个优秀的 Few-shot Prompt 要在"足够说明任务"和"尽量少用 Token"之间找平衡点
- **ICL 的具体体现**：样本提示就是 In-Context Learning 的实践形式

## 关键要点

- **示例质量 > 示例数量**：3 个精心挑选的好示例通常优于 8 个随意的示例
- **示例顺序有影响**：把多样性最强的示例放在前面，可以提高模型泛化
- **示例格式一致性**：所有示例的输入输出格式保持完全一致——一个格式跑偏的示例会让模型困惑
- **何时升级**：Zero-shot 效果不好时加 One-shot，还不够加 Few-shot。但如果 Few-shot 也不行，考虑 Fine-tuning
