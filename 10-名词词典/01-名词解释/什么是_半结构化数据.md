# 半结构化数据（Semi-structured Data）

> 介于结构化与非结构化之间的一种数据形态：**有一定自描述性结构（如标签、键值对），但不强制要求严格的数据模型约束**。JSON、XML、日志文件是最常见的例子。

## 是什么

半结构化数据的核心特征是**先有数据，后有结构**：

- 数据自带结构标记（JSON 的 `{}` 和 `key:value`、XML 的 `<tag>`），但同一批数据中各条记录的结构可以不一致
- 不像关系型数据库那样需要预先定义 Schema（表结构），可以灵活扩展新字段
- 人和机器都能直接读懂，适合数据交换和 API 通信

典型例子：电子邮件的元数据（发件人、主题、正文——有的邮件有附件字段，有的没有）、网页 HTML、日志文件、配置文件（YAML/TOML）。

## 为什么重要

- **API 时代的主力格式**：几乎所有 LLM API（OpenAI、Anthropic 等）的请求和响应都是 JSON
- **RAG 的数据源**：企业知识库中大量内容以 JSON/XML（如 Confluence 导出）或 Markdown（前端）格式存在
- **数据管道的中间态**：数据从非结构化（PDF）→ 半结构化（JSON 解析结果）→ 结构化（入库）是常见处理链路

## 关键要点

- **代表格式**：JSON（Web/API）、XML（企业系统/配置文件）、YAML（配置）、Markdown（文档）
- **存储系统**：MongoDB 等文档型数据库、Elasticsearch、对象存储
- **处理技术**：XPath/XQuery（XML）、jq（JSON 命令行工具）、正则 + 解析器（日志）
